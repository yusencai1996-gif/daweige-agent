# 技能创作指南

## 技能是什么

一条技能 = 一份**可复用的干活套路文档**。写清楚"什么活、按什么步骤干、坑在哪",下次遇到同类活,任何一个角色翻到它就能照着干好。**技能只是文字,不带脚本、不带程序**——大微阁的技能是纯 Markdown 文档。

## 文件格式(就三样)

技能 = 一个文件夹 + 里面一个 `SKILL.md`,开头是说明块:

```
---
name: 技能英文名(小写,词间连字符,如 excel-monthly-report)
description: 什么时候用这条技能(一句话,写触发场景不写内容摘要)
---

# 技能标题

(正文)
```

## name 怎么起

- 只用小写英文、数字、连字符:`excel-monthly-report` 合法;`Excel月报`、`excel_report` 不合法
- 照着"活的名字"起:干什么的就叫什么,不起花名

## description 怎么写(最关键的一行)

模型靠这行判断"这活要不要翻这条技能",写偏了技能就白写:

1. **写清触发场景**:什么任务、什么关键词出现时该用(例:"整理照片和文档、按类别归档文件夹的任务")
2. **可以列具体触发词**:如(如:记账、对账、开票、报销)
3. **不写内容摘要**:不要写"本技能介绍了 XX 方法论"——没人靠摘要触发技能
4. **一句话说清"拿到什么活先翻它"**:例:"拿到'领导要点+素材要成稿'的任务先翻这份套路"

好例句:"整理照片/文档/下载目录,要分类归档重命名的任务。用户说'帮我整理 XX 文件夹'时先翻这份套路。"

## 正文怎么写

按这个骨架来,读的人不用动脑就能照做:

1. **第 0 步:接活先确认什么**——干这活前必须问清/核对的两三样东西
2. **步骤套路**——第一步干什么、第二步干什么;每步一句话说清动作和标准
3. **交活自检清单**——`- [ ]` 逐条勾的检查项,漏一条就是事故的那种
4. **不要做**——这个活最容易踩的坑,明确禁止

行文规矩:

- **大白话写口令**,不写论文:写"数字一个都不许编",不写"应确保数据准确性"
- **写做什么,不写为什么**:执行者不需要道理,需要动作
- 有数字标准就给数字(上限、位数、格式),不给"适量""适当"
- 整条技能控制在 **80 行以内**;套路特别长就拆成多条技能

## 大微阁的硬约束(写技能必守)

- **纯 Markdown,零脚本**:正文里不写任何"运行 XX 程序/脚本"的指令;需要程序的活,把步骤写成让人看懂的操作说明
- **给人看的成果默认 Office 格式**(技能正文里涉及交付物时按此引导)
- 技能里**不存密钥、不存个人敏感信息**
- 不抄别人受版权保护的技能内容;参考思路可以,文字要自己写

## 存到哪

- **0.7.0 自产技能只支持写入全局技能文件夹**,写入后所有角色都能用
- **角色专属技能写入后续版本开放**;当前不要尝试写入某个角色的技能文件夹

## 怎么写入(大微阁专用通道)

写技能文件不走普通文件路径,**统一用这个专用地址**(主进程会自动映射到真实技能文件夹,不用也不要去找具体磁盘路径):

```
daweige-skill://global/<技能名>/SKILL.md
```

- 写入前会弹出确认卡,把完整内容展示给用户过目
- 只能新建,不能覆盖已有技能(同名说明已存在,先跟用户确认)
- 写入成功后**新开的对话**才能用这个技能,当前对话不会热加载

## 写完自检(交出技能文件前逐条过)

- [ ] name 合法(小写英文+连字符),没有和已有技能重名
- [ ] description 写的是触发场景,看到它就知道什么活该翻这条
- [ ] 正文有步骤、有自检清单、有"不要做"
- [ ] 没有任何脚本/程序执行指令
- [ ] 80 行以内,通读一遍没有空话
