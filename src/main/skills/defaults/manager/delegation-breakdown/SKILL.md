# 派活拆解套路(总管专用)

## 第一步:要不要派活(先判断,不盲目派)

| 任务特征 | 处理 |
|---|---|
| 一句话能答、不用动文件 | 自己答,不派 |
| 单一角色的活(如"把这张表汇总") | 直接派给对应角色 |
| 多步骤/多角色依赖(如"汇总完让小编写通报") | 拆步骤按序派,上游完成再派下游 |
| 拿不准 | 跟用户说思路,一句话确认再动 |

## 第二步:拆解(复杂任务)

1. 按"产出物"拆步骤:每步要有明确交付(一份汇总表/一篇稿/一个整理完的文件夹)
2. 标依赖:哪些步骤可以并行、哪些必须等上游(账房没算完数,小编不能动笔)
3. 每步指定角色+挂载文件夹(角色干活只在自己的工作区里,需要的素材先确认在它够得着的地方)

## 第三步:派活话术(任务书三要素,缺一不可)

给角色的任务书必须包含:

1. **任务边界**:干什么、干到什么程度算完(如"汇总这批销售表,净额口径,异常单独列")
2. **素材位置**:输入文件在哪、输出放哪
3. **交棒定论**:要求回传"结论+关键数字+产出文件位置",过程细节不用长篇汇报

不要把模糊原话直接转手("帮我弄下那个表"→原样派出去=失职;转述成上面三要素再派)

## 第四步:验收与交棒

1. 下游交付后**对照任务边界验收**:数字对不对、文件在不在,不是"它说完了就完了"
2. 验收不过打回重做,说清哪条没达标;过了再进下一步
3. 全链完成后给用户一份总汇报:每步谁干的、结论是什么、产出在哪

## 不要做

- 不替下游干它的专业活(总管是调度,不是替补)
- 交棒只传定论不传过程;但用户追问过程时能查得到记录
- 上游没完成不硬派下游(拿半成品让下游"将就一下")
